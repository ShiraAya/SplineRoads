# SR 端点体系升级：Codex 实施约束（修订版 v2）

> 本文件完整替换第一份《SR 端点体系升级：Codex 实施约束》。本次修订根据后续两张车道点／匝道需求图，以及用户要求修改第一份的确认，取消道路附属端点在匝道连接器中的汇出选路与汇入定位用途；其余不冲突的端点升级要求保留。条款编号继续沿用，E5改为点类型与工具权限边界。

> 两份文档配合使用时，第二阶段旧文档中“上一份允许附属端点用于匝道”属于已失效的历史描述；“是否继续保留该旧入口”不再是待确认事项。不得以兼容旧图或旧文档为由恢复该入口。车道点与新匝道连接器的具体实现仍属于第二阶段。

## 0. 任务范围与依据

本任务以原三张手写需求图为基础，并按后续车道点／匝道需求及本次用户确认修订，实现“道路附属端点”“自动端点优化”“符合条件的分段道路在立交等操作中视为同一条道路”。先完成本阶段，再进入第二阶段的车道点体系与匝道连接器重做。

当前匝道连接器已经删除实现，只保留空物品。本阶段禁止恢复旧连接器源码、交互、界面、路径生成及自动控制点逻辑，也不得借本任务提前重写连接器。车道点的创建工具、UI及新连接器交互在第二阶段实现。

本阶段为后续功能保留道路身份与引用、连续道路范围、实际占用和冲突检查等基础能力，但不得将道路附属端点预设为匝道接入点，也不得建立“匝道必须依赖附属端点”的数据关系。不能将“基础接口已准备”写成“车道点或匝道功能已完成”。

**已经确定的新选点规则：匝道连接器先选择汇出起点，再选择汇入点；起点只能是车道点，汇入点只能是车道点或路口端点（中心点）。道路附属端点不参与该连接器的汇出选路、汇入定位或其他代选流程。** 原图中这两项旧用途已经取消，不是延期到第二阶段再实现。

第1—3节保留原图要求，并在涉及匝道用途处按本次确认显式修订；第4—6节是为实施和验收补充的约束；第7节是仍未明确的边界，不得冒充已确定要求。不得再以“原图仍画了附属端点汇入”为由恢复已撤销的用途。

先阅读当前实际工程，再确定修改位置。不得虚构现有类名、接口和实现情况。工程现状与需求冲突时，应指出冲突并提出修改方案，不能偷偷删减需求。保持当前工程的版本与依赖，不自行扩大到其他功能重构。

### 字母约定

图1中的C是附属端点；图2、图3中的B是真实道路端点，两者不是同一种点。

为避免跨图混淆，本文将图1的附属端点C改记为P，原道路仍称AB；多个附属端点记为P1、P2等。图2、图3统一使用“A—B—C”，其中AB、BC为两个实际路段，整体范围称A至C。字母重命名本身不改变各点的含义；涉及匝道用途的修改由第0节及E3、E5规定。P始终表示道路附属端点，不能将其悄悄改称车道点。

## 1. 道路端点升级——对应图1

### E1. 创建附属端点，不拆分道路

新增道具“端点创建器”。使用该道具右键已有道路，在点击位置生成属于该道路的附属端点P。

创建后，AB仍是一条完整道路，A、B仍是真实道路端点。禁止通过把AB拆成AP、PB两条独立道路来代替附属端点功能。一条道路必须支持多个附属端点，不能只支持一个。

### E2. 自动端点操作与附属端点的位置关系

对AB进行自动端点操作时，调整对象仍是真实端点A、B，不能把P当作新的道路末端。

操作前后，P的世界坐标X、Z不变；Y根据路面情况变化，使其保持在道路上。不能用“保持道路长度百分比不变”来代替“世界坐标X、Z不变”，导致道路伸缩时P沿路移动。

此规则针对自动端点操作，不得据此禁止玩家按E4主动调整附属控制点。

### E3. 附属端点作为整条道路的选择入口，但不适用于匝道连接器

P可以单独选择。立交连接器等需要选择整条道路、且按本需求支持附属端点的工具，通过P应能解析到所属道路AB及其真实端点A、B，达到选择AB的效果。不得错误地只选AP或PB，不得将P直接替换成AB的某一个末端。立交主路附属端点仍受E7的特别限制。

**删除原E3中“通过附属端点选择匝道汇出道路”的用途。** 本条的整路选择能力不向匝道连接器开放，不能将“可选择整条道路”实现为所有工具都自动接受P。

不得在匝道连接器中先选择P，再自动寻找、创建或转换一个车道点来继续建造，以此绕过新的选点规则。未来匝道的具体车道与接入位置由玩家选中的合法车道点或路口中心点决定，不由P代选。

### E4. 手动调整道路形状

对于平滑曲线道路，P还能作为控制点，允许调整X、Y、Z来调整道路的贝塞尔曲线；其余道路的附属点只允许调整Y。

必须同时保留E2的自动操作限制和本条的手动调整能力，不能把两者合并成同一种操作。多个附属控制点不能覆盖彼此的数据。

“曲线是否必须穿过附属控制点”的具体语义，原图未明确，按第7节处理，不得自行用一种实现冒充已经确认的设计。

### E5. 道路附属端点与车道点分离，取消附属端点的匝道接入用途

**原E5“附属端点作为匝道汇入点”已撤销。** 道路附属端点既不能作为匝道汇出点，也不能作为匝道汇入点；这不是仅隐藏UI而仍在接口中保留旧入口。

| 点的类型 | 新匝道连接器的汇出起点 | 新匝道连接器的汇入点 |
| --- | --- | --- |
| 车道点 | 允许，仍须满足第二阶段的道路范围与建造校验 | 允许，仍须满足第二阶段的道路范围与建造校验 |
| 路口端点（中心点） | 不允许 | 允许，按第二阶段的路口接入规则处理 |
| 道路附属端点P | 不允许 | 不允许 |
| 普通道路端点A、B | 不允许 | 不允许，不能混同于路口中心点 |

道路附属端点和车道点必须在语义、归属与工具权限上区分。即使位于同一处，也不能仅因坐标重合而视为同一种点。不得把所有附属端点批量改名为车道点、自动附加匝道权限，或为兼容旧选点方式保留隐式转换。

道路附属端点继续承担E3的非匝道整路选择、E4的形状调整、E6的标线分段等既定功能。车道点按第二阶段要求仅用于匝道连接，不因本次修订继承道路调形或标线分段能力。两类点的创建和使用不能互相冒充，也不能要求玩家先创建附属端点才能使用车道点。

本条明确的是两个阶段之间的类型与权限边界，不要求本阶段提前实现车道点工具、车道点UI或新连接器。

### E6. 以附属端点划分标线编辑区间

P将AB的地面标线编辑范围划分为AP、PB，标线编辑器可以分别设置两部分的地面标线。

多个附属点应形成相应的连续编辑区间，例如AP1、P1P2、P2B。修改一个区间不能覆盖其他区间的设置。此处分的是标线编辑范围，不是把实际道路拆成多个独立路段。

### E7. 立交主路的特别限制

立交主路也允许设置附属端点，但只能发挥原图“作用4”，即E6的标线分段功能。

不能把普通道路附属点的整路选择、形状控制等能力直接套用到立交主路附属点上。“只能发挥作用4”是特例，优先于前面的通用能力。无论普通道路还是立交主路，附属端点都不具备E5已取消的匝道汇出／汇入用途。

## 2. 自动端点优化——对应图2

### A1. 新增允许调整的非自由端点

在A—B—C中，B是真实道路端点，连接AB与BC，不是附属端点。对其中一段进行自动端点操作时，不得仅因为B不是自由点就直接拒绝调整。

新增调整能力须满足原图条件①及补充限制：B不属于路口；相邻两段为车道数相同的直线道路；道路属于A2的适用范围；实际道路不可有起伏高低变化。

需要判断整段道路实际形状与高程，不能只因首尾等高便忽略中间起伏。图示为共线衔接的两段，折角情况及具体几何容差按第7节处理。

如果所选路段的另一端A也不是自由点，且其相邻道路同样满足条件，也应允许对应调整，不能只实现某一个方向或某一个端点。

### A2. 本轮优化适用范围

适用于所有的自动高架道路；桥梁类别中的跨线桥、小河桥梁、高架；所有的地面道路。上述范围包括普通道路和高速道路。

这份范围针对本节的自动端点优化，不能擅自拿来缩减第1节附属端点的适用范围。图中没有列出的其他桥型等，不得自行扩展为已要求支持的对象。

### A3. 调整共享端点时，两侧道路同步变化

原图示例为：调整前AB＝100米、BC＝100米；移动B后，AB＝150米、BC＝50米。

在这个示例中，A、C位置保持不变，B改变的是两侧路段的长度分配。AB、BC必须共享调整后的同一个B，仍然连续衔接，不能只修改一侧，不能留下旧接缝、重复道路或断口。

调整前后道路样式不能改变。两侧路段各自已有的样式设置必须保留，不能为了方便重建而统一套用其中一段的配置。

### A4. 附属端点位置固定，允许改变所属路段

参与上述操作的道路可以包含附属点，不能因为存在附属点就一律禁用优化。

操作后附属点位置不变。若B移动后，原来属于AB的附属点落入BC范围，则将其归属改为BC；反向从BC改属AB同理。

这是所属对象迁移，不是把点移动到新位置，也不是删除后另建一个无关的点。相关标线分段与引用不得因迁移而丢失或错配。

本条的对象仅为道路附属端点P，不表示P还承担匝道连接引用，也不自动规定未来车道点的位置保持与归属迁移方式。车道点的对应联动细节在第二阶段单独确认。

### A5. 保留已有匝道保护，但不再将附属端点作为匝道锚点

原图“调整时保护预先连接的匝道，并在匝道妨碍自动端点操作时判定失败”的意图保留。按本次修订，匝道连接不再建立在附属端点P上，不能继续实现“匝道挂在P上并随P归属迁移”的旧关系。

当自动端点操作不妨碍已有匝道、且可以保留其有效连接时，不能仅因为某个附属端点P从AB改属BC，就搬动、删除或重新接入该匝道。已有连接的保护和冲突检查应依据实际道路、接入位置及占用关系，而不是假定P就是接入点。

例如自动立交因已有匝道而无法生成时，自动端点仍应判定失败。不能为了成功而忽略匝道冲突、擅自删除或搬动匝道，也不能反过来把“存在任何匝道”一律当成失败条件。

本阶段为这项规则准备可接入的道路引用与检查机制；未来由车道点或路口中心点接入的新匝道在第二阶段联调。车道点如何在共享端点移动、道路变形后更新位置和归属，并未因本次取消旧入口而一并确定，不能直接套用P的规则。

尚未存在的连接器实机行为必须标为待第二阶段联调，不能拿模拟对象通过测试代替真实连接验收，也不能为了验收本条而恢复旧连接器或旧附属端点接入方式。

## 3. 满足条件的分段道路视为同一条道路——对应图3

### C1. 操作时视为同路，不永久合并实际路段

满足图2条件①及其范围、高程限制的道路，在立交、匝道等相关操作中视为同一条道路。这里保留的是连续道路范围识别，不是附属端点的匝道选点权限。

第二阶段匝道连接器在需要连续范围时，应从合法选中的车道点及其所属道路取得相应范围，不能通过P选路，不能把所选车道点替换成范围末端，也不能抹掉具体车道和接入位置。路口中心点仍按第二阶段的路口接入规则处理。

连续范围可用不代表所有道路都可被新匝道连接器选取；仍须遵守第二阶段的道路类型、立交归属及建造检查。反过来，本节用于连续范围识别的直线、无高低起伏等条件，不能扩写为全部匝道建造的统一门槛。

AB、BC仍保留原有实际分段，未被占用限制时，道路编辑器仍可分别编辑。禁止为了实现连续道路识别而永久合并道路对象、删除真实中间端点B，或强迫玩家先手动合并。

编辑后若不再满足识别条件，应停止把它们视为同一条道路。特别是出现高低起伏时，不得继续沿用修改前的同路判定。

### C2. 连续道路识别不依赖“自动调整”开关

原图示例：AB＝200米、BC＝100米，某项立交建造要求所选方向至少有250米道路。

若AB、BC满足连续道路识别条件，即使关闭自动调整，也应使用A至C范围内实际连续的道路长度完成判断，并从A起取得满足建造要求的实际范围。

这不是修改显示数字，也不是仅把长度检查从200改成300。后续预览、实际生成、连接和占用计算，都必须真实使用需要延伸到BC的部分。

若所需范围恰为从A起250米，则会使用AB的200米以及BC内的50米；不能仍按200米生成，也不能把“使用A至C范围”理解为任何情况下都强制占满300米。

关闭自动调整时，不得为了通过检查而偷偷移动B。连续范围识别与真实端点移动必须区分。

### C3. 实际占用到的相邻路段也必须限制编辑

按上述方式建成立交后，即使立交名义上归属于AB与另一条道路，只要实际侵占了BC，BC也不能再用道路编辑器编辑。

因此必须区分“最初选择或名义关联的道路”和“实际被立交占用的道路”，不能只锁定前者而漏掉BC。

道路编辑器的限制，不等于禁止第1节明确允许的立交主路标线编辑。不得将这两种工具的权限混为一谈。

## 4. 补充的实施与数据安全约束

### I1. 不用局部假实现代替完整行为

选取、几何计算、预览、实际建造、碰撞、标线与编辑限制应遵守一致的道路和端点关系。不能只有界面识别连续道路，生成器仍使用原来的单段范围；也不能只改客户端显示，不更新实际保存的数据。

匝道连接器与立交生成器内部的匝道不是同一个功能范围。不得借“连接器已删除”顺手删除现有立交匝道或其他正常功能。

### I2. 保存与重载不能破坏结果

附属点的位置、所属道路、控制信息、标线区间，以及立交的实际占用关系，必须在保存和重载后保持正确。存在客户端/服务端同步的部分，也必须同步一致。

归属迁移应保留稳定身份或等效的可靠引用机制，不强制指定类名和字段结构。旧存档缺少新增字段时不能崩溃或丢失道路；迁移不得恢复已经删除的连接器实现，也不能将附属端点自动转换成车道点来迁就旧数据。若实际发现旧数据依赖已取消的接入方式，应单独说明并确认迁移处理，不能静默损坏既有道路或连接。

### I3. 失败操作不能留下半成品

跨路段调整应作为一个完整操作处理。两侧道路、附属点归属、标线与占用关系不能只更新一部分。

若新位置、依赖关系或建造检查不合法，应保留操作前的有效状态，并给出具体失败原因。不得通过放松原有冲突检查、隐藏错误、返回成功状态来凑通过。

### I4. 占用限制应随真实依赖更新

立交删除或实际占用变化后，应重新检查相关路段的编辑限制；仍被其他结构占用的路段不能误解锁，不再被占用的路段不能永久锁死。

几何、车道配置或连接关系改变后，应更新连续道路判定。不能把“曾经是同路”当作永久属性。

不得无说明地新增“必须完全相同样式”“只允许某一个建造方向”等门槛来缩减已明确要求。工程确实存在额外兼容问题时，先说明问题及影响。

## 5. 实施顺序与进度记录

先完成源码核查及需求对应关系，再按依赖推进：端点与引用数据、保存同步 → 附属点创建/选择/形状调整/标线分段 → 共享真实端点调整与归属迁移 → 连续道路范围及立交实际占用 → 回归验收。

不要求重写整个SR，也不指定未经源码核实的架构。能复用的正确实现可以复用，但不得复活被删除的匝道连接器。

对第1—3节的每项编号记录“已实现且已验证”“已实现但未验证”“仅完成接口、待第二阶段联调”“未完成/待确认”。不能把完成计划、创建空方法或通过编译当作功能完成。

实施清单、接口权限、测试、UI提示和文档都必须按本修订更新。原E3中匝道汇出选路和原E5中附属端点汇入功能应标记为“已撤销”，不得继续列为待实现、待联调或待确认。现有实现若已接入旧方式，需检查并取消该入口，同时保留附属端点的其他功能；不得以只改文字或隐藏按钮代替权限修订。

第7节的问题先核查当前工程是否已有明确规则；仍无法确定且会改变玩家操作结果的，集中确认后再实现对应部分。不要因此搁置与歧义无关的已明确工作。

## 6. 最低验收场景

| 场景 | 必须检查的结果 |
| --- | --- |
| 在AB右键创建一个及多个附属点 | 点可用，AB仍为一条完整道路；不能用实际拆路代替。 |
| 通过附属点进行非匝道整路选择、分段编辑标线 | 立交连接器等适用工具的整路选择得到所属AB；各标线区间可独立设置，不串段。不包括匝道连接器选路。 |
| 点类型与匝道入口分离 | 本阶段检查数据与接口未把P授权为匝道起终点、未把P转换成车道点。第二阶段实际验证：匝道连接器不能通过P或普通道路端点选起终点；起点只选车道点，汇入只选车道点或路口中心点。第二阶段结果不得在本阶段冒报通过。 |

## 7. 原图未明确、不得自行定案的边界

**控制点语义与交互：** 平滑曲线是否必须经过附属控制点，还是允许它作为脱离曲线的贝塞尔控制柄；坐标调整具体沿用哪个工具或界面。不能把其中一种解释假定为原图已经确认。

**连续道路的具体判定：** “车道数相同”按总数还是分方向数量比较；折角直线、恒定纵坡是否符合条件；普通道路与高速、不同桥型或不同横断面样式之间能否连续识别。原图没有给出完整兼容规则，也没有给出几何判断的数值容差。

**位置与边界冲突：** 自动调整后附属点原X、Z不再落在路上、附属点恰好与真实端点重合时，如何处理。不能未经确认就擅自移动、删除点，或将其升级为真实端点。

**删除与区间继承：** 删除附属点后两侧标线如何合并，删除或改建所属道路时附属点及其引用如何处理。原图没有规定具体继承策略。

**连续识别的延伸范围：** 原图展示两段道路，是否要求递归识别三段及更多道路、如何确定延伸终点，需要确认。不能声称原图已完整规定，也不要把示例中的200、100、250米或恰好两段写死在算法里。

**第二阶段车道点联动：** 新车道点在道路调整、共享端点移动后的坐标、所属道路／车道与已有匝道引用如何维护，由第二阶段单独确认。取消旧附属端点的匝道用途，不等于这些联动细节已经全部确定。若工程确有旧附属端点接入数据，其迁移方式也需基于真实数据明确。

**不再待确认的边界：** 道路附属端点不能用于匝道连接器的汇出选路或汇入定位；不得自动转换、代选或保留旧入口作为替代路径。“是否恢复附属端点匝道用途”不应继续列入本轮或第二阶段的待确认事项。

这些边界的确认不能推翻已明确的要求：附属点不拆路；自动操作保持其水平位置；满足条件的共享真实端点可以调整；连续道路识别不依赖自动调整开关；实际侵占BC就必须限制BC的道路编辑；附属端点的非匝道整路选择、形状控制和标线分段功能保留，立交主路仍仅允许标线分段；匝道起点只选车道点，汇入只选车道点或路口端点（中心点）；本阶段匝道连接器仍保持空物品，车道点及连接器重做留在第二阶段。
