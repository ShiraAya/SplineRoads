# R3/R4已实现内容、真实构建与边界

## R3保留车道分离

保留车道分离现在是独立TEMPORARY模式：所选车道直连匝道，主路下游暂时取消该车道，匝道真正让出通行空间后渐变恢复。旧BRANCH改显示为“普通分流（原车道直行）”，持久化含义不变，不加载世界时擅自关闭旧路。DETACH仍为整车道分离，EXTRA仍为额外扩出。

新增LaneReopening沿原始车道位置检查最终匝道路面与结构体：最后一次不安全的下游相交决定恢复，不是固定A后若干格，也不是中轴稍离开就恢复。上方板厚、既有净空规则、桥墩/斜梁保守体积包围均参与；已有结构规划结束后在RoadData稳定阶段再次检查实际临时范围。恢复需要渐变长度和安全余量；段内无法安全恢复则拒绝，不强行重叠。预览显示相对A的恢复起点和完整断面恢复点。

源接头净空豁免收窄为所选槽位附近，不能把整条双向宿主含对向车道都当合法接头。分离可以从A起坡，不再因源接触区拟合一直贴住主路。没有关闭碰撞或全局净空检查。

边界：仍是各方向最外侧车道；不能挖走内部槽位/把单向单车道主路清空；自动恢复限同一稳定断面实际路段，不跨车道数变化接缝。道路自由尽头没有主路下游则不生成恢复段。真实世界放置、保存重进、多人及车辆AI未实测。

## R4热缓存

CPU几何和设施只构建一份，路面/标线从共同设施层分离。VBO依普通/扩展顶点格式分别保存，两份GPU表示共用不可变Prepared数据；切换复用有效缓冲，不能把普通格式绑定扩展格式。Oculus实际BufferBuilder扩展受WorldRenderingSettings.shouldUseExtendedVertexFormat控制，已核查官方1.20.1-new源文件，不只根据是否安装模组判断。

terrain关闭时撤下活动模型，将Prepared tile移入有界缓存，开启后优先直接恢复；真实图集改变时仅使带旧UV/sprite的表示失效，保留中立面索引。旧异步结果不得恢复已编辑/删除模型。实际改路、灯光变化、淘汰和世界退出仍允许必要重建。

配置config/splineroads-client.toml中的rendering：

```toml
surfaceBackend = "AUTO"
inactiveVboCacheMiB = 64
terrainCacheMiB = 64
```

两个64为额外休眠缓存估算预算，不是整个模组总内存或精确显存。0关闭保留。显存格式/资源失效或缓存超限后允许重传。活动区段不无限驻留。光影切换仍需要Minecraft区块管线刷新，不能保证整个切换零成本。
