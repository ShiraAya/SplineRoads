# 0.40.6最终补充：不要让单条改路承担全图空间索引构建

最终复查发现，合成基准有2000次查询，足以摊销新建索引；但玩家只改一条路时，不应照搬相同策略。本条补充并限定0406-performance.md中的候选索引描述。

RoadPlanningIndex现在按事务实际待规划数量选择：少于256条待规划记录，或世界候选不超过64条，直接沿用原精确全列表过滤，不建立全图边界对象/分桶；较大批量才建立空间候选索引。256是保守的批量启用门槛，不是已由用户存档调优的最佳参数。

两个路径都保留原3/82格谓词、顺序、多支撑面并集、排除自身、每次替换后的最新几何/结构。RoadData初次规划和依赖重规划均传当时built.size()。生产单次独立StructurePlanner入口默认小操作路径。无标签栅格快路径和世界线程不变。

局部测试将大小批量两条路径同时对照原列表：1500步替换，6301检查通过（原3300检查扩展），没有提前栅格化。最新完整Forge/回归以最后应用提交的artifact为准，不发布旧中间产物。

没有声称单条操作因为空间索引就更快；其收益来自本轮另外的重复结构栅格和碰撞形状复用。用户真实地图的主要耗时仍需计时汇总。此后不扩展任务，收尾保存。
