# SR 下一阶段需求：以用户最新明确说明为准

本文件保存的是需求，不是已完成功能。源码基线为用户修正编译后的 `SR.zip`。

## R1 车道数过渡标线

用户截图显示两车道/三车道过渡出现斜线或跨断面错误。须核查原始代码并建立复现，不以截图猜测代替定位。

要求检查增车道与减车道、道路参考方向相反、单向与双向、靠左与靠右行驶。分界线按同一行驶方向内的车道关系过渡，不能穿越中央隔离带、画到对向车道或留下无关端帽。保持应连续的路面、标线、护栏和设施衔接。未经过客户端验证不得声称截图问题已完全消失。

## R2 双向整车道分离

取消“只支持单向主线”的功能限制，但不能只删除报错条件。按所选车道实际通行方向改造对应半幅，保护对向车道、中央隔离带与无关设施。

整车道分离的含义：所选车道先直连匝道，原道路下游取消该车道。车道关系、铺装/碰撞断面、标线、护栏、预览、保存、编辑和删除恢复需一致。没有额外确认时，不擅自放宽净空和碰撞检查。

## R3 保留车道分离（已明确，不再待确认）

用户最后的手绘图和文字明确规定：

> 所选车道先和整车道分离一样上跨/下穿连接匝道，然后在匝道不会影响原车道后再恢复该车道。

两种模式对照：

- 整车道分离：所选车道直连匝道 → 原道路取消该车道。
- 保留车道分离：所选车道直连匝道 → 原道路暂时取消/封闭该车道 → 匝道不影响该车道正常行驶后再恢复该车道。

不得把第二种做成“原车道从头到尾不变，再叠一条分支”，也不得继续引用助手此前错误的“用户未确认”表述来拒绝或撤销本需求。

恢复条件需要根据实际匝道路面/结构与原车道通行空间判断，不能只按固定距离或只看两条中轴是否分开。上跨和下穿都要覆盖；具体几何阈值以工程已有合理设置为依据，缺失的关键参数应明确说明。

## R4 双渲染后端缓存

无光影用旧 VBO，光影包实际参与渲染时用 terrain。用户希望每套仅需加载一次，以避免每次切换重复准备 mesh。

实现目标：同一道路、同一有效资源/格式代次，在缓存仍有效且未被淘汰时，切换复用已准备的结果。不要求无界保留整个世界两份网格，也不能承诺游戏或光影本身完全没有区块重建。

分别识别可共享的几何、两后端表示、GPU 格式、纹理图集和活动区段。真改路/删除/资源重载/不兼容格式改变时正确失效；过期异步任务不得恢复旧模型。缓存应有容量/淘汰策略，切换时不能重复绘制两个完整路面、遗留资源或误清未变化的公共几何。

## 不变的基础约束

- 保留 `SR.zip` 中用户已经做好的编译修正，不改回旧基线。
- 道路附属端点与车道点分离；匝道起点只选车道点，汇入只选车道点或路口中心点。
- 无关普通道路的建造/更新/删除不能触发全图匝道重新选线。
- 自由匝道与后续收费站连接仍是核心目标；不用手调曲线控制点完成合理空间内的组合布局。
- 需求、实现、离线测试、完整构建与实机验证分开记录。
